Dưới đây là node `t2` hoàn chỉnh theo đúng stack bạn đang chạy (ESPHome + HA trong Docker Compose trên `exlinct`), dùng native API chứ không qua MQTT.

## 1. Phần cứng & đấu nối

Board khuyến nghị: **Wemos D1 mini** (`d1_mini`). Nếu bạn dùng NodeMCU thì đổi `board: nodemcuv2`.

| DHT22 (bản 4 chân) | ESP8266 | Ghi chú |
|---|---|---|
| Pin 1 — VCC | 3V3 | Không dùng 5V, DATA sẽ lên 5V theo VCC |
| Pin 2 — DATA | D5 (GPIO14) | Cần pull-up |
| Pin 3 — NC | — | Bỏ trống |
| Pin 4 — GND | GND | |

- **Điện trở pull-up 4.7kΩ giữa DATA và 3V3 là bắt buộc** với DHT22 trần. Datasheet khuyến nghị 4.7kΩ, dải 1k–10k thường vẫn chạy. Module 3 chân đã có sẵn pull-up trên board, nhưng không phải lúc nào cũng có — nếu đọc chập chờn thì hàn thêm.
- Tránh các chân strapping: D0 (GPIO16 — không có interrupt/pull-up nội), D3 (GPIO0), D4 (GPIO2), D8 (GPIO15). D5/D6/D7 là an toàn nhất.
- Dây tín hiệu giữ dưới 1m. Nếu dài hơn 20cm, thêm tụ 100nF ngay chân VCC–GND của cảm biến.

## 3. `t2.yaml`

```yaml
substitutions:
  node_name: t2
  friendly_name: "Tầng 2"
  dht_pin: GPIO14          # D5 trên Wemos D1 mini
  temp_offset: "0.0"       # hiệu chỉnh sau khi so với nhiệt kế chuẩn

esphome:
  name: ${node_name}
  friendly_name: ${friendly_name}

esp8266:
  board: d1_mini
  restore_from_flash: false   # node chỉ đọc sensor, không cần ghi flash

logger:
  level: INFO                 # DEBUG chỉ khi cần xem raw DHT

api:
  encryption:
    key: !secret api_key_t2
  reboot_timeout: 0s          # HA restart thì node không tự reboot theo

ota:
  - platform: esphome
    password: !secret ota_password

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
  power_save_mode: none       # modem-sleep gây rớt API trên ESP8266
  fast_connect: false         # mạng nhiều AP cùng SSID → để nó chọn AP khỏe nhất
  ap:
    ssid: "${node_name}-fallback"
    password: !secret ap_password

captive_portal:

sensor:
  - platform: dht
    pin: ${dht_pin}
    model: DHT22              # KHÔNG để AUTO_DETECT, hay nhận nhầm thành DHT11
    update_interval: 15s
    temperature:
      name: "Nhiệt độ"
      id: t2_temp
      accuracy_decimals: 1
      filters:
        - filter_out: nan     # DHT22 trả NaN khi checksum lỗi
        - median:
            window_size: 4
            send_every: 4
            send_first_at: 2  # có giá trị sau ~30s thay vì chờ 1 phút
        - offset: ${temp_offset}
    humidity:
      name: "Độ ẩm"
      id: t2_hum
      accuracy_decimals: 0
      filters:
        - filter_out: nan
        - median:
            window_size: 4
            send_every: 4
            send_first_at: 2
        - clamp:
            min_value: 0
            max_value: 100

  - platform: template
    name: "Điểm sương"
    id: t2_dewpoint
    unit_of_measurement: "°C"
    device_class: temperature
    state_class: measurement
    accuracy_decimals: 1
    update_interval: 60s
    lambda: |-
      const float t = id(t2_temp).state;
      const float rh = id(t2_hum).state;
      if (isnan(t) || isnan(rh) || rh <= 0.0f) return {};
      const float a = 17.62f, b = 243.12f;
      const float alpha = logf(rh / 100.0f) + (a * t) / (b + t);
      return (b * alpha) / (a - alpha);

  - platform: wifi_signal
    name: "WiFi signal"
    update_interval: 60s
    entity_category: diagnostic

  - platform: uptime
    name: "Uptime"
    entity_category: diagnostic

binary_sensor:
  - platform: status
    name: "Trạng thái"

  - platform: template
    name: "Nồm ẩm"
    device_class: problem
    lambda: |-
      if (isnan(id(t2_hum).state)) return {};
      return id(t2_hum).state > 85.0f;
    filters:
      - delayed_on: 10min
      - delayed_off: 10min

text_sensor:
  - platform: wifi_info
    ip_address:
      name: "IP"
      entity_category: diagnostic

button:
  - platform: restart
    name: "Khởi động lại"
    entity_category: config
```

Vài lựa chọn có chủ đích trong config này:

- `filter_out: nan` đứng **trước** `median`: DHT22 thỉnh thoảng lỗi checksum, nếu NaN lọt vào median thì cả cửa sổ hỏng.
- `update_interval: 15s` + median 4 mẫu = HA nhận 1 giá trị/phút, nhưng đã lọc nhiễu. Đọc DHT22 nhanh hơn 2s là vô nghĩa vì chính cảm biến lấy mẫu ~2s/lần.
- `reboot_timeout: 0s` — mặc định ESPHome reboot node sau 15 phút mất API. Với sensor thuần thì reboot không giúp gì, chỉ làm mất data khi bạn restart HA container lâu.

## 4. Deploy

```bash
cd ~/smarthome
nano esphome/t2.yaml          # paste config
docker compose exec esphome esphome config /config/t2.yaml   # validate trước
```

Lần đầu phải flash qua USB. Hai cách:

**Cách A — cắm vào Pi 5.** Thêm vào service `esphome` trong `docker-compose.yml`:

```yaml
    devices:
      - /dev/ttyUSB0:/dev/ttyUSB0
```

```bash
docker compose up -d esphome
docker compose exec esphome esphome run /config/t2.yaml --device /dev/ttyUSB0
```

**Cách B — flash từ Mac mini.** Vào `http://exlinct.local:6052`, chọn node `t2` → Install → **Manual download** → chọn **Factory format**, rồi mở `https://web.esphome.io` bằng Chrome, Connect, chọn file `.bin`. D1 mini clone dùng chip CH340, macOS từ Sonoma đã có driver sẵn, không cần cài thêm.

Từ lần thứ hai trở đi chỉ cần OTA qua dashboard.

## 5. Verify

1. **Xem log:** `docker compose exec esphome esphome logs /config/t2.yaml`. Mong đợi dòng kiểu `[D][dht:048]: Got Temperature=28.4°C Humidity=72.1%`.
2. **Nếu thấy `Invalid readings! Please check your wiring (pull-up resistor, pin number)`** — đây là lỗi phổ biến nhất với DHT22 trên ESP8266. Kiểm tra theo thứ tự: pull-up 4.7kΩ có thật không → đúng chân GPIO14 chưa → thử `model: DHT22_TYPE2` (một số lô hàng dùng timing khác) → cuối cùng thử đổi sang D6/D7.
3. **Nếu giá trị nhảy loạn hoặc lệch hẳn:** thường là nguồn. D1 mini cấp qua USB adapter rẻ tiền hay bị sụt áp — đo 3V3 bằng đồng hồ, phải ≥ 3.2V ổn định.
4. **HA:** Settings → Devices & Services, `t2` sẽ tự discovery qua mDNS (HA của bạn đang chạy `network_mode: host` nên mDNS thông). Nhập API encryption key khi nó hỏi.
5. **Hiệu chỉnh offset:** để node chạy 30 phút cho ổn định nhiệt, so với nhiệt kế chuẩn, rồi sửa `temp_offset` và OTA lại. DHT22 gắn sát board thường đọc cao hơn thực tế 1–3°C do ESP8266 tự sinh nhiệt — đây là nguyên nhân sai số lớn nhất, lớn hơn sai số của chính cảm biến.
6. **Test rớt mạng:** tắt HA container, node vẫn phải giữ WiFi và tự reconnect khi HA lên lại, không reboot.

## 6. Lưu ý lắp đặt

Vỏ in 3D phải **có khe thoáng ở cả trên và dưới** — hộp kín làm độ ẩm trễ hàng chục phút và gần như vô dụng. Đặt cảm biến ở mặt dưới hoặc bên hông hộp, **không bao giờ đặt phía trên module ESP** vì khí nóng bốc lên. Vị trí treo lý tưởng: cao 1.2–1.5m, tránh nắng trực tiếp, tránh luồng gió điều hòa và tránh tường ngoài hướng Tây.

## 7. Nhân bản cho các tầng khác

Khi làm tiếp `t1`, `t3`, tách phần chung ra `common/floor-sensor.yaml` rồi mỗi node chỉ còn:

```yaml
substitutions:
  node_name: t3
  friendly_name: "Tầng 3"
  dht_pin: GPIO14
  temp_offset: "-1.5"

packages:
  base: !include common/floor-sensor.yaml

api:
  encryption:
    key: !secret api_key_t3
```

Sửa filter hay thêm sensor một lần là áp dụng cho cả nhà. Bạn muốn mình viết luôn bản tách package, hay thêm phần automation HA so sánh chênh lệch nhiệt độ giữa các tầng để điều khiển quạt thông tầng?
