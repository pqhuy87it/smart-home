Tốt, DHT11 dùng để test toàn bộ chuỗi thì hoàn hảo — rẻ, có sẵn, và nếu nó lên được thì mọi thứ khác cũng sẽ lên.

Một lưu ý về độ chính xác để anh không nhầm sau này: DHT11 cho **±2°C, ±5%RH và độ ẩm chỉ trả về số nguyên**. Đủ để xác nhận hệ thống chạy, không đủ để dùng thật lâu dài. Khi nào chốt xong thì thay bằng SHT30 (~50k) là xong, config chỉ đổi vài dòng.

## Bước 1 — Đấu dây

Cấp nguồn cho DHT11 từ **3.3V**, không phải 5V. GPIO của ESP8266 **không chịu được 5V**, và nếu cấp 5V cho DHT11 thì chân DATA sẽ đưa mức 5V vào GPIO. DHT11 hoạt động bình thường ở 3.3V.

| DHT11 | ESP8266 (D1 mini / NodeMCU) |
|---|---|
| VCC / `+` | **3V3** |
| GND / `-` | GND |
| DATA / `S` | **D2** (= GPIO4) |

Chọn GPIO4 vì nó không phải strapping pin. **Tránh GPIO0, GPIO2, GPIO15** — chúng quyết định chế độ boot, và nếu DHT11 kéo mức logic sai lúc reset thì board không khởi động được.

Nếu anh dùng **module DHT11 3 chân** (loại có PCB nhỏ) thì đã có điện trở pull-up 10kΩ sẵn, không cần thêm gì. Nếu là **cảm biến 4 chân trần** thì phải tự mắc **10kΩ giữa DATA và 3V3**, nếu không sẽ đọc ra NaN liên tục.

## Ba điều nên biết về ESP8266

1. **Chỉ có ~40KB RAM khả dụng.** API encryption ăn khá nhiều. Nếu board reboot ngẫu nhiên hoặc log báo hết heap, bỏ khối `api.encryption` đi (chỉ dùng `api:` trơn) — vẫn chạy tốt trong LAN nhà.

2. **Đặt cảm biến xa board.** Module ESP8266 tự sinh nhiệt 3–5°C. Kéo DHT11 ra bằng dây 10–15cm, nếu không số nhiệt độ sẽ luôn cao hơn thực tế.

3. **Nguồn phải khoẻ.** ESP8266 hút tới 300mA lúc phát WiFi. Sạc điện thoại cũ 500mA hay cắm vào USB hub yếu sẽ gây reboot ngẫu nhiên mà không có log gì. Thêm **tụ 470µF** ở chân 3V3–GND nếu thấy bất ổn.

Khi node này chạy ổn định vài giờ, anh có nền tảng đã kiểm chứng để nhân bản ra các tầng và sang node bể nước. Cần tôi viết luôn dashboard HA để xem các node theo tầng chưa?

# Phần 2 — Kiểm tra Mac có nhận board

Cắm board vào MacBook. **Dùng cáp USB data thật** — cáp sạc chỉ có dây nguồn là nguyên nhân số một của "máy không nhận board".

```bash
ls /dev/cu.*
```

Kết quả mong đợi, tuỳ chip UART trên board:

```
/dev/cu.usbserial-0001     # CH340 / CH9102
/dev/cu.SLAB_USBtoUART     # CP2102 (driver Silicon Labs)
/dev/cu.usbmodem14201      # CP2102 driver native của Apple
```

**Dùng `cu.*`, đừng dùng `tty.*`.** Trên macOS, `tty.*` sẽ block chờ tín hiệu DCD và làm esptool treo. Đây là bẫy chỉ có trên macOS.

## Nếu không thấy gì

Xem macOS có nhận thiết bị USB nào không:

```bash
system_profiler SPUSBDataType | grep -A 6 -i -E "serial|ch34|cp21|uart"
```

- **Không có gì cả** → cáp không có dây data, hoặc board chưa được cấp nguồn. Đổi cáp trước tiên.
- **Thấy thiết bị nhưng không có `/dev/cu.*`** → thiếu driver.

macOS 11 trở lên đã có driver cho **CP2102** và phần lớn **CH340** sẵn trong kernel. Nhưng **CH9102** (dùng trên nhiều board D1 mini clone mới) thì thường phải cài driver WCH. Nếu cần, tải từ trang chính thức của WCH, cài rồi **cấp quyền trong System Settings → Privacy & Security** (macOS sẽ chặn kernel extension lần đầu và cần restart).

Trên Apple Silicon còn có thêm một bước: nếu là kext, phải bật **Reduced Security** trong Recovery Mode. Driver mới của WCH là dạng DriverKit nên không cần — ưu tiên bản đó.

Dùng venv thay vì `pip install --break-system-packages` để không làm bẩn Python hệ thống trên máy làm việc của anh.

## Xác nhận kết nối và đọc thông tin chip

```bash
esptool.py --port /dev/cu.usbserial-0001 chip_id
```

Kết quả tốt:

```
Detecting chip type... ESP8266
Chip is ESP8266EX
Features: WiFi
Crystal is 26MHz
MAC: xx:xx:xx:xx:xx:xx
```

Ghi lại MAC — dùng để đặt DHCP reservation sau.

## Xoá flash (khuyến nghị cho lần đầu)

```bash
esptool.py --port /dev/cu.usbserial-0001 erase_flash
```

ESP8266 lưu WiFi credentials trong một vùng flash riêng mà firmware mới không ghi đè. Nếu board từng dùng cho project khác, dữ liệu cũ có thể gây xung đột. Xoá sạch trước là chắc chắn nhất.

## Flash

```bash
cd ~/Downloads

esptool.py --port /dev/cu.usbserial-0001 --baud 460800 write_flash 0x0 sensor-t2.factory.bin
```

Ba chi tiết:

- **Địa chỉ `0x0`** — bắt buộc với file factory của ESP8266, vì nó chứa bootloader từ offset 0. Đừng dùng `0x1000` (đó là cho ESP32).
- **`--baud 460800`** nhanh và ổn định trên hầu hết board. Nếu báo lỗi checksum hoặc timeout giữa lúc ghi, hạ xuống `115200`.
- Không cần `--chip esp8266`, esptool tự nhận.

Log thành công:

```
Configuring flash size...
Flash will be erased from 0x00000000 to 0x0009ffff...
Compressed 655360 bytes to 442310...
Writing at 0x0009c000... (100 %)
Wrote 655360 bytes (442310 compressed) at 0x00000000 in 11.2 seconds...
Hash of data verified.
Leaving...
Hard resetting via RTS pin...
```

Dòng **`Hash of data verified`** là thứ cần thấy. Nếu thiếu nó thì flash chưa toàn vẹn — chạy lại.

4. **Open Folder** → `/home/huy/smarthome`

Từ đó anh sửa `esphome/secrets.yaml`, `docker-compose.yml`, `homeassistant/configuration.yaml` bằng VS Code như file local — có syntax highlight, tìm kiếm, git. Terminal tích hợp chạy trực tiếp trên Pi.

Cài thêm extension **YAML** của Red Hat để bắt lỗi thụt lề trước khi save.

## Cách 3 — Ghi thẳng bằng lệnh SSH

Nếu chỉ cần điền `api_key` và không muốn mở editor:

```bash
cd ~/smarthome/esphome

# Xem hiện tại có gì
cat secrets.yaml
```

Nếu chưa có dòng `api_key`, thêm vào:

```bash
echo 'api_key: "DAN_KEY_VAO_DAY"' >> secrets.yaml
```

Nếu đã có dòng `api_key` và cần thay giá trị:

```bash
sed -i 's|^api_key:.*|api_key: "DAN_KEY_VAO_DAY"|' secrets.yaml
```

Kiểm tra lại:

```bash
cat secrets.yaml
chmod 600 secrets.yaml
```

## Nhưng có thể anh không cần làm gì cả

Wizard **Add new device** thường tự ghi `api_key` vào `secrets.yaml` rồi. Kiểm tra trước khi sửa:

```bash
grep -n api secrets.yaml ../esphome/sensor-t2.yaml 2>/dev/null
```

Hai khả năng:

- **Key nằm trong `secrets.yaml`** → xong, không cần làm gì. File `sensor-t2.yaml` sẽ tham chiếu `!secret api_key`.
- **Key nằm trực tiếp trong `sensor-t2.yaml`** dưới dạng chuỗi base64 → cũng chạy được bình thường. Nhưng nên chuyển sang secrets để sau này commit git không lộ key.

Đằng nào thì key cũng nằm sẵn trong một trong hai file — anh chỉ cần copy nó ra khi thêm device vào Home Assistant ở bước cuối.

## Về việc sửa file trên Pi bằng terminal

Nếu anh muốn dùng editor trực tiếp qua SSH thì `nano` có sẵn, đơn giản nhất:

```bash
nano ~/smarthome/esphome/secrets.yaml
# Ctrl+O rồi Enter để lưu, Ctrl+X để thoát
```

Với `vim`, nhớ `:set paste` trước khi dán để tránh auto-indent làm hỏng YAML.

---

Chọn **Shared** — đó chính là `secrets.yaml`. Bản ESPHome này gọi tên hiển thị là "Shared" thay vì tên file, nên anh không thấy chữ `secrets.yaml` trong dropdown. Tôi nói sai ở lượt trước, xin lỗi anh.

Hai lựa chọn có nghĩa là:

| Dropdown | Ghi vào đâu | Dùng khi |
|---|---|---|
| **Shared** | `secrets.yaml` — dùng chung cho mọi device | ✅ Chọn cái này |
| `sensor-t1.yaml` | Chỉ riêng device đó | Chỉ khi cần giá trị khác nhau cho từng board |

Ảnh thứ hai xác nhận điều đó: `wifi_ssid` và `wifi_password` đang nằm trong `secrets.yaml` (do wizard tự ghi), chỉ là dashboard hiển thị chúng dưới nhãn Shared.

## Việc cần làm

1. Chọn **Shared** trong dropdown
2. Name: `api_key`
3. Value: đã dán đúng — chuỗi 44 ký tự kết thúc bằng `=`, đúng định dạng base64 32 byte
4. **Add secret**

Sau đó thêm luôn `ota_password` (cũng vào Shared), vì config tôi viết có tham chiếu `!secret ota_password`:

```
Name:  ota_password
Value: một mật khẩu dài anh tự đặt
```

Nếu thiếu nó thì lúc build sẽ báo `Secret 'ota_password' not defined`.

## Xác nhận

Sau khi thêm xong, danh sách Secrets phải có 4 dòng: `wifi_ssid`, `wifi_password`, `api_key`, `ota_password`.

Kiểm tra từ SSH cho chắc:

```bash
cut -d: -f1 ~/smarthome/esphome/secrets.yaml
```

Rồi vào card `sensor-t1` → **Edit** → dán config (nhớ `device_name: sensor-t1`) → **Save** → **Install → Manual download**.

---

Không cần thêm `device_name` vào đâu cả — nó là `substitutions`, và anh chỉ cần nó nếu dùng cấu trúc `packages` mà tôi viết trước. Nhìn vào code hiện tại thì wizard đã sinh config đầy đủ rồi, `name: sensor-t1yaml` đang thay cho `${device_name}`.

Nhưng có **một lỗi cần sửa ngay**: lúc chạy wizard anh đã nhập tên là `sensor-t1.yaml` thay vì `sensor-t1`, nên ESPHome ghép thành:

- File: `sensor-t1yaml.yaml` (thấy ở tiêu đề)
- `name: sensor-t1yaml`
- Fallback AP: `sensor-t1.yaml Fallback Hotspot`

Cái này sẽ chạy được, nhưng hostname mDNS thành `sensor-t1yaml.local` — khó nhớ và khó nhìn. Sửa bây giờ dễ hơn sửa sau khi đã flash.

## Cách sửa: dán thẳng config hoàn chỉnh

Panel bên phải là editor YAML. Chọn hết (Cmd+A trong vùng đó) rồi dán:

```yaml
esphome:
  name: sensor-t1
  friendly_name: "Cảm biến tầng 1"

esp8266:
  board: nodemcuv2
  restore_from_flash: false

logger:
  level: INFO

api:
  encryption:
    key: !secret api_key

ota:
  - platform: esphome
    password: !secret ota_password

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
  power_save_mode: none
  reboot_timeout: 15min
  ap:
    ssid: "sensor-t1-setup"
    password: !secret ota_password

captive_portal:

# ---- DHT11 ----
sensor:
  - platform: dht
    pin: GPIO4
    model: DHT11
    update_interval: 60s
    temperature:
      name: "Nhiệt độ"
      filters:
        - filter_out: nan
    humidity:
      name: "Độ ẩm"
      filters:
        - filter_out: nan

  - platform: wifi_signal
    name: "WiFi RSSI"
    update_interval: 120s
    entity_category: diagnostic

  - platform: uptime
    name: "Uptime"
    update_interval: 120s
    entity_category: diagnostic

text_sensor:
  - platform: wifi_info
    ip_address:
      name: "IP"
      entity_category: diagnostic

button:
  - platform: restart
    name: "Restart"
    entity_category: config
```

**Giữ nguyên dòng `key:`** đang có trong file — hoặc nếu dán đè thì `!secret api_key` sẽ tự lấy từ Shared secrets mà anh vừa thêm, nên không mất gì.

Bấm **Save**.

## Đổi tên file

Đổi `name:` trong YAML **không** tự đổi tên file. Sửa qua SSH:

```bash
cd ~/smarthome/esphome
mv sensor-t1yaml.yaml sensor-t1.yaml
```

ESPHome yêu cầu tên file trùng với `name:`. Refresh dashboard sau khi đổi.

## Về hai cách làm việc

Giao diện Device navigator bên trái là **wizard trực quan** — bấm từng mục để thêm component qua form. Với anh thì dùng editor YAML bên phải nhanh hơn nhiều, đặc biệt khi nhân bản node cho các tầng khác: chỉ copy file rồi sửa 2 dòng.

Về `substitutions` và `packages`: chưa cần dùng lúc này. Khi anh có 4–5 node giống nhau thì mới đáng tách phần chung ra. Config phẳng như trên dễ debug hơn cho node đầu tiên.

## Bước tiếp theo

1. **Save**
2. `mv` file qua SSH, refresh dashboard
3. Nút ba chấm trên card → **Install** → **Manual download** → **Modern format (factory)**
4. Mang file `.factory.bin` sang MacBook, flash theo hướng dẫn trước

Trước khi flash, nhớ đấu DHT11: **VCC → 3V3**, **GND → GND**, **DATA → D2** (GPIO4 trên NodeMCU).
